一、项目概述
================================================================

项目名称：基于Java的二手书交易平台
技术栈：
  后端：Spring Boot 3.4.5 + MyBatis + MySQL 8.0
  前端：Vue 3 + Element Plus + Vite + Axios
  认证：JWT（JSON Web Token）
  构建：Maven 3.x

项目功能：
  一个完整的二手书在线交易平台，支持三种角色：
  - 管理员：后台管理所有数据
  - 买家：浏览、搜索、购买二手书，评价订单
  - 卖家：上架、管理书籍，处理订单

六、核心业务流程
================================================================

【1. 用户登录流程】
前端 Login.vue → POST /login（用户名+密码+角色）
  → 后端 CommonController.login()
  → 查询对应角色表验证密码
  → 生成 JWT token 返回
  → 前端存储 token 和用户信息到 localStorage
  → 跳转到对应首页

【2. 书籍购买流程】
浏览书籍 → 加入购物车 → 购物车结算
  → 创建订单（status=0 待支付）
  → 买家支付（status=1 待发货，扣除余额）
  → 卖家发货（status=2 待收货，填写快递单号）
  → 买家确认收货（status=3 已完成，余额转给卖家）
  → 买家评价

【3. 订单状态流转】
0(待支付) → 1(待发货) → 2(待收货) → 3(已完成)
0(待支付) → 4(已取消)
1(待发货) → 5(申请退款) → 6(退款完成)
2(待收货) → 5(申请退款) → 6(退款完成)

【4. 文件上传流程】
前端选择文件 → POST /file/upload（multipart/form-data）
  → 后端 FilesController 保存到 uploads/ 目录
  → 返回文件访问 URL
  → 前端将 URL 存入对应字段

十、安全认证机制
================================================================

【1. JWT 认证流程】

本项目使用 JWT（JSON Web Token）实现无状态身份认证：

(1) 用户登录时，后端验证用户名密码，验证通过后生成JWT token
(2) JWT 使用 HS256 算法签名，密钥为配置的固定字符串
(3) Token 有效期为 30 天
(4) Token 中包含用户信息：id、username、nickname、type（角色类型）
(5) 前端收到 token 后存储在 localStorage

【2. 请求拦截机制】

LoginInterceptor（登录拦截器）工作流程：
(1) 拦截所有请求（/** 路径）
(2) 排除不需要登录的接口：/common/login、/common/register、/file/**
(3) 对于 OPTIONS 预检请求直接放行（支持CORS）
(4) 从请求头 "token" 字段获取 JWT token
(5) 如果 token 为空，返回 401 状态码
(6) 验证 token 有效性（签名、过期时间）
(7) 解析 token 中的用户信息，存入 ThreadLocal
(8) 请求处理完毕后清除 ThreadLocal，防止内存泄漏

【3. 用户信息传递】

CurrentUserThreadLocal 工具类：
- 使用 ThreadLocal<CurrentUserDTO> 在同一请求线程内传递当前用户信息
- 拦截器 preHandle 中 set()，afterCompletion 中 clear()
- Controller/Service 层通过 CurrentUserThreadLocal.getCurrentUser() 获取

【4. 跨域配置】

CorsConfig 配置类：
- 允许所有来源（*）的跨域请求
- 允许所有 HTTP 方法（GET/POST/PUT/DELETE 等）
- 允许所有请求头
- CORS 预检缓存时间为 24 小时

【5. 角色权限设计】

三种角色通过 type 字段区分：
- ADMIN：管理员，可访问后台管理所有功能
- USER：买家，可浏览书籍、下单购买、评价
- SHOP：卖家，可管理自己的书籍和订单
注意：当前系统通过业务逻辑代码（if判断type）控制权限，
      而非使用 Spring Security 等框架级别的权限控制。

十一、推荐算法说明（协同过滤）
================================================================

本项目实现了基于协同过滤的书籍推荐功能，包含三种推荐算法：

【1. 用户-商品评分矩阵构建】

评分规则（多种用户行为加权）：
  浏览记录 = 1 分
  收藏记录 = 2 分
  购买记录 = 3 分
  评价记录 = 评价星级分数

示例：用户A浏览了书籍X（+1分）、又收藏了书籍X（+2分）→ 
      用户A对书籍X的总评分 = 3分

【2. 基于用户的协同过滤（User-Based CF）】

原理：找到与目标用户行为相似的用户，推荐这些相似用户喜欢但
      目标用户未接触过的书籍。

步骤：
(1) 构建用户-商品评分矩阵
(2) 使用余弦相似度计算用户之间的相似度
(3) 找出与目标用户最相似的用户群体
(4) 从相似用户喜欢的商品中筛选目标用户未交互过的商品
(5) 按加权评分（相似度 × 评分）排序，取Top-N推荐

余弦相似度公式：
  sim(A,B) = (A·B) / (||A|| × ||B||)
  其中 A·B 为两个用户评分向量的点积
  ||A|| 和 ||B|| 为各自向量的模

【3. 基于物品的协同过滤（Item-Based CF）】

原理：找到与用户已交互商品相似的其他商品进行推荐。

步骤：
(1) 构建用户-商品评分矩阵
(2) 转置为商品-用户矩阵
(3) 使用余弦相似度计算商品之间的相似度
(4) 对用户已交互的每个商品，找出最相似的未交互商品
(5) 按相似度累加排序，取Top-N推荐

【4. 混合推荐（Hybrid）】

策略：将用户协同过滤和物品协同过滤的结果合并
- 一半名额分配给 User-Based CF
- 一半名额分配给 Item-Based CF
- 合并后去重
- 如果推荐数量不足，用热门商品（按销量排序）补充

【5. 冷启动处理】

当用户没有任何行为记录（新用户）时：
- 不使用协同过滤
- 直接返回热门商品（按销量倒序排列）

【6. 首页推荐去重机制】

RecommendationController 的 homepage 接口：
- 先获取协同过滤推荐列表
- 记录已推荐的商品ID
- 获取普通推荐时排除已推荐的商品
- 确保两个推荐区域不出现重复书籍

十三、异常处理机制
================================================================

【1. 自定义异常类 CustomException】

继承 RuntimeException，携带 HTTP 状态码和错误消息。
两种构造方式：
- CustomException(String msg)：默认使用 409 CONFLICT 状态码
- CustomException(HttpStatus status, String msg)：自定义状态码

【2. 全局异常处理器 GlobalExceptionHandler】

使用 @ControllerAdvice + @ExceptionHandler 注解：
- 捕获所有 CustomException
- 将异常信息封装为 ResponseVO（code + msg）
- 返回对应的 HTTP 状态码

【3. 业务异常场景举例】

订单操作：
- "订单不存在"           → 409
- "订单状态不允许此操作"  → 409
- "库存不足"             → 409

购物车操作：
- "只有买家才能添加书籍到购物车" → 409

登录认证：
- "用户类型错误"         → 409
- "token无效"           → 401 UNAUTHORIZED

【4. 订单状态机】

系统通过状态转换映射表控制订单状态流转的合法性：
  状态0(待支付)   → 可转为 1(待发货) 或 4(已取消)
  状态1(待发货)   → 可转为 2(待收货) 或 5(申请退款)
  状态2(待收货)   → 可转为 3(已完成) 或 5(申请退款)
  状态3(已完成)   → 终态，不可转换
  状态4(已取消)   → 终态，不可转换
  状态5(申请退款) → 可转为 6(退款完成)
  状态6(退款完成) → 终态，不可转换

任何非法状态转换都会抛出 CustomException。

十四、统一响应格式
================================================================

所有API接口返回统一的 ResponseVO 格式：

成功响应：
  { "code": 200, "msg": "操作成功", "data": <具体数据> }

失败响应：
  { "code": <HTTP状态码>, "msg": "操作失败", "data": <错误信息> }

分页数据使用 PageVO 封装：
  { "list": [<数据列表>], "total": <总记录数> }

十六、Service 层详细说明
================================================================

【BookOrderServiceImpl 订单服务核心逻辑】

1. createOrder（创建订单）：
   - 校验书籍是否存在、库存是否充足
   - 生成订单号：BO + 年月日时分秒 + 4位随机数
   - 自动设置卖家ID（从书籍中获取）
   - 自动设置买家ID（从当前登录用户获取）
   - 计算总金额 = 单价 × 数量
   - 初始状态为0（待支付）

2. pay（支付）：
   - 将订单状态从0改为1
   - 扣减书籍库存

3. ship（发货）：
   - 将订单状态从1改为2
   - 记录快递单号

4. cancel（取消）：
   - 如果订单处于待发货状态(1)，需恢复库存
   - 将状态改为4（已取消）

5. approveRefund（审批退款）：
   - 恢复书籍库存
   - 将状态改为6（退款完成）

【ShoppingCartServiceImpl 购物车服务核心逻辑】

1. insert（加入购物车）：
   - 只有买家（USER）角色才能操作
   - 如果该书籍已在购物车中，合并数量
   - 否则新增购物车记录

2. createOrder（购物车批量下单）：
   - 遍历选中的购物车项
   - 逐一创建订单
   - 下单成功后删除对应购物车项
   - 如果部分下单失败，收集错误信息统一提示
